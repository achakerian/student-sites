# Student Sites — lifecycle runbook

How this project is run, wound down, kept dormant at zero cost, and brought back
for the next class. Written so that any of these can be done cold, from this
document alone, in under half an hour.

Design goal for every phase: **published student sites stay live forever; everything
else is disposable.**

---

## 0. What exists

| Component | Lives in | Cost when live | Cost when dormant | Needed for published sites to stay up? |
|---|---|---|---|---|
| GitHub Pages site (`student-sites.org`) | this repo, `main` branch | free | free | **yes** |
| Student sites | `students/<slug>/` on `main` | — | — | **yes** (they *are* the content) |
| `students/sites.json` manifest | generated by `.github/workflows/manifest.yml` on push to `main` | free | free, runs only when `students/**` changes | yes (index reads it) |
| Student pages `/start`, `/submit`, `/review` | static HTML on `main` | free | free | no |
| Starter kit `start/starter.zip` | built from `template/` by `scripts/build-starter.sh` | free | free | no |
| Cloudflare Worker `student-sites-submit` | Cloudflare account, code in `worker/` | free tier (100k req/day) | free — or deleted | no |
| GitHub fine-grained PAT `student-sites-worker` | GitHub → Settings → Developer settings | — | expires (14 days) or revoked | no |
| Worker secrets `GITHUB_TOKEN`, `PASSCODE` | Cloudflare (set via `wrangler secret put`) | — | gone when Worker deleted | no |

Nothing above needs renewing, paying for, or monitoring while dormant. The only
credentials that ever exist are the PAT and the passcode, and both are created
fresh per activity and destroyed at sunset.

## 1. Operate (during an activity week)

**Daily, ~5 minutes:** open `https://student-sites.org/review/`. For each card:
preview → *Open PR* → **Merge** (publish) or **comment + Close + Delete branch** (reject).

**Nothing else is scheduled.** The Worker, Action and Pages run themselves.

### Symptom → cause → fix

| Symptom | Cause | Fix |
|---|---|---|
| Students get *"Something went wrong on our side"* on submit | PAT expired/revoked, or Worker not deployed | Create a new PAT (§4 step 2), then `cd worker && npx wrangler secret put GITHUB_TOKEN` |
| *"That passcode isn't right"* for everyone | Passcode secret differs from worksheet | `cd worker && npx wrangler secret put PASSCODE` |
| *"Couldn't reach the server"* on submit page | Worker deleted, or `WORKER_URL` wrong in `submit/index.html` | `cd worker && npx wrangler deploy`; check the URL matches |
| Review card preview is blank / "no longer available" | The PR was merged or closed (branch deleted) — expected | Nothing; refresh the queue |
| Merged site not on the index | Manifest Action failed or hasn't run | Actions tab → *Update site manifest* → re-run, or *Run workflow* manually |
| Index shows stale list | Browser cache of `styles.css`/`api.js` (Pages caches 10 min) | Hard refresh. `sites.json` itself is already cache-busted |
| Review page says *rate limit reached* | >60 unauthenticated GitHub API calls/hour from your IP | Wait, or use the *All PRs on GitHub* link |
| Worker suddenly 500s mid-week | PAT hit its 14-day expiry | New PAT + `secret put GITHUB_TOKEN` (≈3 min) |

### Changing things mid-week

Follow §5 (SDLC). Site pages go live ~1 min after merge to `main`. Worker changes
additionally need `cd worker && npx wrangler deploy` — this is deliberate: there is no
Cloudflare token in GitHub, so deploys are always a human action from a logged-in
laptop.

## 2. Sunset (end of the activity)

Do these in order. Total ≈ 15 minutes. Each step says what breaks if you skip it.

**1. Empty the review queue.**
```
gh pr list --search "Site:" --state open
```
Merge or close every one. Close with `--delete-branch` so no unreviewed content
lingers on a public branch:
```
gh pr merge <n> --merge --delete-branch
gh pr close <n> --delete-branch --comment "Submissions have closed for this activity."
```
*Skip it and:* unreviewed student work stays visible on GitHub branches indefinitely.

**2. Delete any stray `site/*` branches** (from PRs closed without `--delete-branch`):
```
git fetch --prune
git branch -r | grep 'origin/site/' | sed 's#origin/##' | xargs -I{} gh api -X DELETE repos/achakerian/student-sites/git/refs/heads/{}
```
*Skip it and:* same as above.

**3. Close the submit page.** Replace the `<form>` … `</form>` block and the
`<div id="notice">` in `submit/index.html` with:
```html
<div class="notice">
  <strong>Submissions are closed.</strong> Thanks to everyone who took part —
  published sites stay up on the <a href="../">index</a>.
</div>
```
and remove the `<script>` block. Commit as `Close submissions for <activity name>`.
On `start/index.html`, change the "Submit your site" button text to "Submissions
closed" and drop its `href`. Commit and push.
*Skip it and:* students hit a confusing server error instead of a clear message.

**4. Delete the Worker.**
```
cd worker && npx wrangler delete
```
This removes the code, its URL, and both secrets from Cloudflare.
*Skip it and:* nothing costs money, but a live endpoint with a repo-write token
keeps existing for no reason.

**5. Revoke the PAT.** https://github.com/settings/personal-access-tokens →
`student-sites-worker` → **Revoke**. Do this even though the Worker is gone and
even though the token would expire anyway.
*Skip it and:* a credential with write access to the repo stays valid until expiry.

**6. Tag the activity** so the state of the repo — sites, template, worksheet —
is recoverable by name:
```
git tag -a activity-2026-08 -m "MQBS1000 vibe-coding week, Aug 2026"
git push origin activity-2026-08
```

**7. Verify the dormant state** (all three must hold):
```
curl -s -o /dev/null -w "%{http_code}\n" https://student-sites.org/                                  # 200
curl -s -o /dev/null -w "%{http_code}\n" https://student-sites.org/students/<any-slug>/            # 200
curl -s -o /dev/null -w "%{http_code}\n" https://student-sites-submit.achakerian.workers.dev/submit  # 000 or 404/530
```

**What deliberately stays:** the published sites, the index, `/start` (as a read-only
explainer), `/review` (read-only; shows "Recently decided", previews will 404), the
Worker source in `worker/`, the manifest Action, the starter kit, and this document.

## 3. Dormant (between activities)

**Upkeep: none.** No secrets exist, no services are running beyond GitHub Pages, and
no dependency needs updating for the published sites to keep serving — they are
plain HTML.

Things that may *look* like they need attention and don't:

- **Dependabot alerts on `worker/package-lock.json`** — the Worker isn't deployed.
  Deal with them at relaunch (§4 step 1), not before.
- **The manifest Action** — only runs if `students/**` changes. It won't.
- **The custom domain certificate** — GitHub renews it automatically.

If a published site must be taken down (complaint, student request): `git rm -r
students/<slug>`, commit, push. The Action rebuilds the manifest; the folder stays
in git history unless you also rewrite it.

## 4. Relaunch (next activity) — ≈ 20 minutes

**1. Update the Worker's dependencies** (dormancy may be months):
```
cd worker && npm install && npm audit fix && npm test        # expect all green
```
Commit the lockfile if it changed.

**2. Create a new PAT** — https://github.com/settings/personal-access-tokens/new
- Name `student-sites-worker`, expiry = length of the activity + a few days
- Repository access: *Only select repositories* → `achakerian/student-sites`
- Permissions: **Contents: Read and write**, **Pull requests: Read and write**. Nothing else.

**3. Deploy the Worker.** The Cloudflare account and `achakerian.workers.dev`
subdomain persist, so the URL comes back identical and `submit/index.html` needs
no change:
```
cd worker
npx wrangler login          # only if the laptop is new
npx wrangler secret put GITHUB_TOKEN
npx wrangler secret put PASSCODE       # pick a new passcode each time
npx wrangler deploy
```

**4. Reopen the submit page** — revert the sunset commit from §2 step 3:
```
git log --oneline | grep "Close submissions"      # find it
git revert <sha>
git push
```

**5. Decide what to do with the previous cohort's sites.** Either:
- *Keep them* on the index (nothing to do), or
- *Clear them*: `git rm -r students/*/ && git commit -m "Clear sites from activity-2026-08"`
  (they remain reachable at the tag). Never delete `students/sites.json` — the Action
  owns it.

**6. Refresh the starter kit and worksheet.** Edit `template/` if the rules changed
(`CLAUDE.md` and `PROMPT.md` must stay identical apart from the intro block), then:
```
scripts/build-starter.sh
```
Update `docs/worksheet.md` with the new passcode and dates. The QR code
(`docs/qr-start.png`) only needs regenerating if the URL changes.

**7. Smoke-test end to end** — do this the day before, not during class:
```
# wrong passcode → 401 with friendly message
curl -s -F slug=test-site -F names=Test -F passcode=wrong -F file=@start/starter.zip \
  -H "Origin: https://student-sites.org" https://student-sites-submit.achakerian.workers.dev/submit
# real submit → ok:true with a PR URL
curl -s -F slug=test-site -F names=Test -F passcode=<real> -F file=@start/starter.zip \
  -H "Origin: https://student-sites.org" https://student-sites-submit.achakerian.workers.dev/submit
```
Then: open `/review/` and confirm the card renders with a preview → merge the PR →
confirm `student-sites.org/students/test-site/` is live and on the index →
`git rm -r students/test-site && git commit -m "Remove smoke-test site" && git push`.

**8. Tag the start** (`activity-YYYY-MM-start`) if you want a clean "before" point.

## 5. SDLC — how changes are made to this repo

Small project, one maintainer, but the rules are the same ones that make a big
project safe. They cost almost nothing here and mean the next relaunch isn't an
archaeology exercise.

**Branching.** `main` is what's live. Work on a branch (`fix/…`, `feat/…`), open a PR,
merge. Direct pushes to `main` are acceptable for one-line content fixes during an
activity; anything touching `worker/`, `scripts/` or `.github/` goes through a PR.
Student submissions are PRs by construction.

**Branch protection.** Not currently enabled — see the trade-off note below. Minimum
recommended: a ruleset on `main` blocking force-push and deletion (no workflow
impact). Full protection (require PR for all changes, no bypass) also blocks the
Worker's token from ever writing to `main`, but requires moving manifest generation
out of a commit into a Pages deploy workflow first. Decide at relaunch.

**Tests — run before merging anything that touches them:**
```
cd worker && npm test                              # Worker: validation, GitHub client, preview, handler (47 tests)
node --test scripts/build-manifest.test.mjs        # manifest generator (3 tests)
```
Static pages have no test suite; check them with `python3 -m http.server 8000` and a
browser, and syntax-check inline scripts with `node --check` on the extracted block.

**Deploys.**
- Site: automatic on push to `main` via GitHub Pages (~1 min).
- Worker: manual, `cd worker && npx wrangler deploy`, from a logged-in laptop. No CI
  deploy on purpose — it would require storing a Cloudflare API token in GitHub.
- Starter kit: `scripts/build-starter.sh`, then commit `start/starter.zip`.

**Secrets.** Never in the repo. Only two exist (PAT, passcode), both live only in
Cloudflare Worker secrets, both are recreated per activity and destroyed at sunset.
`worker/.dev.vars` is git-ignored for local testing.

**Dependencies.** `worker/` is the only place with any. Lockfile committed; `npm audit`
at each relaunch; bump `wrangler` and `vitest` majors only at relaunch, never mid-week.

**Documents.** Design spec and implementation plan live in `docs/superpowers/`;
student-facing material in `docs/worksheet.md`; this runbook in `docs/LIFECYCLE.md`.
If a change alters how the system behaves, update the spec in the same PR.

**Commit messages.** Plain imperative, one line, no trailers or tool attribution.

**Tags.** One per activity at sunset (`activity-YYYY-MM`) so a cohort's exact state is
recoverable without spelunking through history.

## 6. Checklists (print-friendly)

**Sunset**
- [ ] All `Site:` PRs merged or closed with branch deleted
- [ ] No `origin/site/*` branches remain
- [ ] `submit/index.html` shows "Submissions are closed"; `start/` button disabled
- [ ] `npx wrangler delete` done
- [ ] PAT revoked on GitHub
- [ ] `activity-YYYY-MM` tag pushed
- [ ] Index 200, a student site 200, Worker URL dead

**Relaunch**
- [ ] `npm install && npm audit fix && npm test` green
- [ ] New PAT (Contents RW + PRs RW, this repo only)
- [ ] Secrets set, `wrangler deploy` done, URL unchanged
- [ ] Sunset commit reverted (submit page open)
- [ ] Old cohort kept or cleared — decided and done
- [ ] Starter kit rebuilt, worksheet passcode/dates updated
- [ ] Smoke test passed and `test-site` removed
